# 精度对比与定位

本文件统一规定标杆对齐和算子开发期间的精度对比与问题定位方法。阶段 2 使用“标杆对齐”，
阶段 4 使用“算子实现定位”；版本、值域校准、误差分析和记录要求只在本文件维护。

统一使用 [CT Tool v0.9.1](https://gitcode.com/Wei_NaChuan/ct/releases/v0.9.1)。从发布页安装
`ct_tool-0.9.1-py3-none-any.whl`，并使用 `ct --version` 确认版本。

## 共同准备

1. 固定被比较代码、输入、随机种子、执行次数、有效数据范围和精度阈值。
2. 将被比较的最终输出和必要中间结果保存为 `.npy`、`.pt` 或 `.pth` 文件。
3. 对每个输出分别记录 shape、dtype、有效区域、比较指标和阈值依据；padding 和无效区不参与比较。
4. 记录 CT Tool 版本、输入数据版本、完整命令和结论。临时输出和内部路径不得写入公开记录。

## 值域校准

正式精度比较前，先确认输入值域能够区分正确结果和代表性错误。CT Tool 用于选择值域和分析
误差形态，已确认的混合容差是标杆对齐和算子验收的唯一 PASS/FAIL 标准。

1. 固定 shape、分支、随机种子、有效区域和混合容差，由小到大调整输入值域并生成候选用例。
2. 对每档值域分别生成正确结果和与当前计算路径匹配的代表性错误结果，例如全零输出、遗漏计算项、
   错误 scale 或错误 head/chunk 映射。
3. 使用
   `ct viz <test_output> <golden_output> --out_dir <output_dir> --name <case_name> --spatial`
   查看正确结果和代表性错误结果的全值域分布、误差分布、空间位置及 `Inf/NaN`。合适的值域应使
   正确结果贴近 `y=x`、误差集中在零附近且没有按 head/chunk 或连续区域聚集，同时使代表性错误
   与正确结果清晰分离。
4. 排除会使合法计算出现溢出、下溢、饱和、非有限值或超过既定数值误差的值域，在剩余候选中选择
   能稳定暴露代表性错误的最小值域。
5. 将选定值域固定到输入生成器，并使用该值域和已确认的混合容差完成全部正式比较。将候选值域、
   混合容差结果、CT 图形结论和最终选择记录到开发期 `docs/validation.md`；正式验收不根据本轮结果
   临时放宽标准。

## 标杆对齐

比较用户参考实现与独立 CPU 标杆时：

1. 先使用结果可人工检查的最小用例确认公式、返回顺序和有效区域，再运行阶段 2 的完整对齐用例。
2. 按“值域校准”选定输入范围，使用已确认的混合容差判断 CPU 标杆与参考实现是否对齐。
3. 混合容差未通过时，执行
   `ct viz <cpu_output> <reference_output> --out_dir <output_dir> --name <case_name> --spatial`，
   查看误差分布、空间位置和 `Inf/NaN`，判断差异来自公式、计算顺序、dtype、无效区还是阈值。
4. 同时具备待测输出、升精度真值和另一份标杆输出时，可以使用
   `ct dual <test> <golden> <benchmark>` 辅助区分误差来源；这不是当前 ATK 混合容差验收的默认入口。
5. 接口未定义的差异返回阶段 1 确认；CPU 标杆有误时在阶段 2 修正。全部差异解决后才能进入阶段 3。

## 算子实现定位

单 Stage 或整算子的 NPU 结果与 CPU 预期不一致时：

1. 按计算顺序比较最终输出和已有 Stage 中间结果，找到第一次出现差异的位置；整算子失败时先
   确定首个出现差异的 Stage。
2. 使用原混合容差复现首个差异结果，再执行 `ct viz --spatial`，确认误差范围、空间分布、
   非有限值和受影响路径。
3. 按原因处理：接口或支持范围不明确时返回阶段 1；CPU 标杆有误时返回阶段 2；设计有误时返回
   阶段 3；计算、同步、搬运、数据排布或写回实现有误时修复阶段 4 代码；测试文件或比较方式有误
   时修正对应测试。
4. 修复后使用相同条件，从最早受影响的 Stage 重新验证到当前目标；全部通过后才能继续开发。
