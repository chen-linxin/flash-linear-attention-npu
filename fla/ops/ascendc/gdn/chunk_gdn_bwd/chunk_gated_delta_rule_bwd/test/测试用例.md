# GDN 反向大融合测试用例

## 1. 精度标杆

每个正式迭代以独立 FP32 PyTorch recurrent reference 为主标杆，覆盖
`o/dq/dk/dv/dbeta/dg`。被修改的局部子图另与固定 commit 的 NPU 小算子
拼接结果做针对性对比，用于区分融合回归和既有误差。

逐输出检查 `o/dq/dk/dv/dbeta/dg` 的 shape、dtype、NaN/Inf 和仓库既有双标杆标准。
不得通过缩小随机范围、跳过失败 case 或放宽阈值完成迭代。

## 3. 反向与非法输入

当前执行 10 个公开 wrapper 异常 case：FP32 主输入、主输入 dtype 不一致、
`q/k/v/g/beta` rank 错误、q/k 与 q/v 前缀不一致、gate/beta shape 不一致、
gate head 不一致、chunk 非 2 的幂。统一 L0 接入后再补充其 metadata、GVA 比例和
状态边界参数校验，不在当前 Python 拼接路径伪造尚未实现的异常行为。

## 4. 性能锚点

| Case | 模式 | B/Seq | T | HK/HV | V | Chunk | dtype |
|---|---|---:|---:|---|---:|---:|---|
| P1 | varlen | 64 seq | 65536 | 32/32 | 128 | 64 | bf16/fp32 gate |

| P4 | dense | B=8 | 8192 | 32/32 | 128 | 128 | bf16/fp32 gate |

Task Duration，并同时记录所有 AIC/AIV pipe、launch 数和 workspace 峰值。
