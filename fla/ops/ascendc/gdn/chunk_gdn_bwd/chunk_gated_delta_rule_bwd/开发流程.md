# GDN 反向大融合开发流程与迭代记录

## 1. 固定目标

- 基线：当前主线 `flash_chunk_gated_delta_rule_bwd` 的小算子拼接。
- 目标：性能锚点上 `融合耗时 / 基线耗时 <= 0.5`。
- 范围：无 CP、无 initial/final state 梯度；dense/varlen、GVA、V128/V256、chunk64/128。
- 指导文档：仓库根 `AGENTS.md` 和 PR 299 的 `docs/agents/`。

## 2. 一轮正式迭代

```text
记录候选改进和预期瓶颈
  -> 修改一个可测因素
  -> Release 编译和安装
  -> 开发烟测
  -> 30 case 正式精度矩阵
  -> 精度全部通过
  -> 固定锚点 profiling
  -> 登记正式迭代
```

精度没有全部通过时：

- 本轮只记入“失败尝试”，不分配正式迭代号。
- 记录首个失败 case、输出、误差形态和根因。
- 修复后重新执行完整正式精度矩阵，不能只复跑失败 case 后登记完成。

## 3. 性能口径

每个性能 case 同时记录：

- 当前小算子链各 Op Type 的 Task Duration 及总和。
- 融合路径各 Op Type 的 Task Duration 及总和。
- 端到端 backward profile 区间。
- kernel launch 数、workspace 峰值、主要 AIC/AIV pipe 和 wait。

```text
ratio(case) = fused_task_duration_sum / baseline_task_duration_sum
```

目标按每个固定锚点判断，不用更换 shape、减少 case 或 Python wall time 制造达标结论。

## 6. 正式迭代记录

只有精度矩阵全部通过后才在此表新增一行。

| 迭代 | 改进点 | 精度 | P1 ratio | P2 ratio | P3 ratio | P4 ratio | 主要瓶颈 | 结论 |
|---|---|---|---:|---:|---:|---:|---|---|
| 1 | WY 反向从 da+full 切换为已有融合入口，消除 `dA` 落盘和一次 launch | 30 正常 + 10 异常通过 | 0.998 | 1.015 | 0.981 | 0.916 | 变长场景 fused Prepare 耗时与两段之和接近 | 单独不接受；保留进入组合路径评估 |
| 2 | 继承迭代 1；head-first fp32 cumsum 整 chunk 搬入 UB，连续标量 forward/reverse scan 后整 chunk 写回 | 30 正常 + 10 异常通过；独立 6 组 cumsum 通过 | 0.889 | 0.881 | 0.892 | 0.791 | `Prepare`、`Dqkwg`、`FwdH` | 接受组合路径；cumsum 耗时降至基线的 0.18-0.19，但整体未达 0.5 |

### Head window 结论

P1 细粒度 profiling 中，`Dqkwg` 的 Cube/Vector 分别约为 14.12/14.17 ms，
`Prepare` 约为 16.21/16.22 ms，`FwdH` 约为 10.45/10.45 ms。C 侧没有比 V 侧
明显更快，且 `Dqkwg` 的 Cube MTE2 活跃占比较高，因此不启用 4-head window，
保持当前 2-head overlap。后续优先减少阶段间 GM/L2 流量。

## 7. 失败尝试

| 日期 | 候选改进 | 首个失败 case | 失败输出/现象 | 根因与处理 |
|---|---|---|---|---|
| 2026-08-15 | 初版 34 case 大矩阵 | 长序列 negative-linear | 候选和基线在相同位置超阈值 | 既有长累积误差；按逻辑分支拆分为 T=64 的 negative-linear 与独立 varlen/GVA/V256 case |
| 2026-08-15 | zero gate 长序列 | T=16/128 zero gate | 候选和基线均失败 | 无衰减累积的既有精度问题；T=2 保留跨 token 递推分支，长累积问题独立跟踪 |
| 2026-08-15 | 使用 Prepare 子算子 CPU helper 作全链标杆 | 首个 CPU/NPU 对比 case | 候选与基线彼此接近，但都与 helper 不一致 | helper 语义不覆盖完整反向链，正式矩阵改用独立 recurrent reference |
| 2026-08-15 | 首版性能输入 | P3 | 长序列输出出现 NaN/Inf | 输入使用零衰减；改为每个 chunk 内确定性负衰减，并重采基线和候选 |
| 2026-08-15 | cumsum 连续 chunk 扫描 v1 | D02，T=63 | AIV 报 UB 地址未对齐 | 扫描步长产生 4B 偏移；改为 UB 中每行 pad 到 8 个 FP32 元素，保证所有 Vector 地址 32B 对齐 |
| 2026-08-15 | cumsum 连续 chunk 扫描 v2 | D03，H=2/T=64 | H=1 尾块通过，但 exact chunk 与多 head 整体失真 | `DataCopyPad` 不会把每个标量扩展成独立 32B 行；改为连续 UB 搬运加标量 scan |

## 8. 最终交付门禁

- 30 case 正式精度矩阵全部通过。
- Custom Operator、Fast-Kernel-Launch、Example/ST 和完整 wheel 验证通过。
- ctypes ABI 契约测试通过。
- fixed/varlen、GVA、V128/V256、chunk64/128 和窗口尾部覆盖。
- racecheck、memcheck、initcheck、synccheck 命中目标 kernel 且无真实问题。
- A2/A3/A5 共用同一 L0 契约；无法上板的 SOC 明确记录未覆盖原因。
- 固定性能锚点达到 0.5 倍目标，或保留完整 profiling 证据说明剩余瓶颈。
