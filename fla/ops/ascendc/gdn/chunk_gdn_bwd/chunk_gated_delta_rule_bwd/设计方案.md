# GDN 反向大融合设计方案

## 1. 目标

当前端到端反向依次执行：

```text
recompute_w_u_fwd
  -> chunk_gated_delta_rule_fwd_h
  -> chunk_bwd_dv_local
  -> chunk_gated_delta_rule_bwd_dhu
  -> chunk_bwd_dqkwg
  -> prepare_wy_repr_bwd_da
  -> prepare_wy_repr_bwd_full
  -> chunk_local_cumsum
```

主线已有 `prepare_wy_repr_bwd`，可替换
`prepare_wy_repr_bwd_da + prepare_wy_repr_bwd_full`。完整目标仍是统一的
`chunk_gated_delta_rule_bwd` L0，不把现有小算子长期保留为融合路径 fallback。

性能目标按 [开发流程](开发流程.md) 中固定锚点统计：

```text
融合反向 Task Duration / 当前小算子拼接 Task Duration <= 0.5
```

## 2. 建议内部原型

```text
inputs:
  q, k, v, g, beta, A, d_o
  cu_seqlens?, chunk_indices?
attrs:
  scale, chunk_size
outputs:
  dq, dk, dv, dbeta, dg
```

`initial_state`、`dht` 和 `dh0` 不进入当前 L0 原型。窗口、SOC、tile、workspace
offset 和模板选择由 host tiling 推导，不增加实现型参数。

## 3. 依赖模型

计算同时包含两类依赖：

- `dV_local`、`dQ/dK/dW/dG` 和 WY 反向是 chunk 内计算。
- `h` 正向状态和 `dH` 反向状态在 chunk 间存在 carry。

同一条 carry 链不能按 chunk 无协议分配给不同 core。首选 task owner 为
`(sequence, qk-head-group)`，owner 负责该组 value head 的完整 chunk 链和
`dq/dk` 组内归约。若沿 V tile 增加并行度，必须显式设计 partial workspace 和归约 owner。

## 4. 两遍流式执行

### 4.1 前向检查点遍

按 sequence/head group 正序处理 chunk：

1. 流式重算当前 chunk 的 `w/u`。
2. 推进前向 `h` 状态。
3. 只保存反向需要的 chunk state checkpoint。

不落完整 `w/u/v_new`。state checkpoint 的 dtype 由独立精度试验决定，长 carry
首选 FP32；公开输出仍遵守接口 dtype。

### 4.2 反向流式遍

按 chunk 逆序：

```text
重算当前 chunk 的 w/u
  -> 计算 dV_local
  -> 更新 dH carry 并得到 dV2
  -> 由 checkpoint 生成 V_new
  -> 计算 dQ/dK/dW/dG
  -> 计算融合 WY backward
  -> 合并 dK/dG
  -> chunk-local cumsum
  -> 写最终梯度
```

`dV_local/dH/dW/dA` 只保留当前 chunk 或 tile 的生命周期。优先使用 UB/L1/CV
直连；无法直连时使用带 ready/free 的双 bank workspace。

## 5. AIC/AIV 和 Head Window

- AIC：GEMM、state 矩阵更新、组内归约和 Fixpipe。
- AIV：gate/exp/mask/cast、逐元素梯度、state row 更新和 cumsum。
- AIC/AIV 使用一致的 `task -> window -> stage -> head -> chunk/tile` 逻辑顺序。
- 每条跨侧数据边必须定义 producer、consumer、ready、free、slot 和最后消费点。
- 两个 Vector subblock 各自持有完整 head 时先评估 2-head。
- 只有完整 timeline 证明 Cube 明显快于聚合 Vector，或存在独立 resident 收益时，
  才保留 4-head。
- L1/L0 跨 head/group 驻留按最小共享 key 设计，与 SOC 无关。

## 6. SOC 和代码分层

- 所有 SOC 共用一个 L0 定义、原型和 L2 调用路径。
- 通用实现按 entry、struct/common、cube、vector 分层。
- A5 专项实现放入 `op_kernel/arch35/`，只在 include/trait/模板层选择。
- TilingData 只保存运行期规模、offset、有效长度、workspace 和调度信息。
- ctypes `GetWorkspaceSize` 声明逐参数对照 C++ 原型，并增加不依赖 NPU 的 ABI 测试。

## 7. 分阶段实施

1. 基线：固定现有八段拼接的精度和 Task Duration。
2. 迭代候选 A：端到端切换到主线已有 `prepare_wy_repr_bwd`，消除 `dA` 输出和一次 launch。
3. 迭代候选 B：新增统一 L0 骨架，先融合反向后半段及最终梯度归并。
4. 迭代候选 C：接入 `dH` carry 和 `dV_local`，消除完整 `dh/dv2/dw` 中间量。
5. 迭代候选 D：接入前向 checkpoint 重算，消除完整 `w/u/v_new`。
6. 在精度通过后，按 profiling 逐项评估 direct path、resident、双缓冲和 head window。

候选名称不是正式迭代号。只有满足 [开发流程](开发流程.md) 的精度门禁后，
才能登记为“迭代 1/2/3”。
